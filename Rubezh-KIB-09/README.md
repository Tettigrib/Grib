# Рубеж · KIB-09

Локальный аудитор готовности малого бизнеса к программам-вымогателям. Владелец или ИТ-специалист оценивает 18 мер и выбирает, что команда может улучшить за доступное время. Для каждой меры можно посмотреть пример подтверждения. Прототип связывает результаты с конкретной работой компании — отгрузкой заказов, передачей макетов или подготовкой отчётности.

## Запуск

Распакуйте архив целиком и откройте `index.html` двойным щелчком. Установка пакетов, регистрация и сервер для демонстрации не требуются. Для постоянного адреса на своём компьютере выполните в каталоге проекта `python -m http.server 8000 --bind 127.0.0.1` и откройте http://127.0.0.1:8000. На Windows можно использовать `py` вместо `python`.

## Демонстрация за две минуты

1. Откройте демо интернет-магазина. Общая оценка составляет 56%, мониторинг — 17%. Нажмите на карточку мониторинга и посмотрите, какие ответы дали такой результат.
2. В плане улучшений выделите 1,5 человеко-дня. Выберите «Провести пробное восстановление». Ресурс исчерпан. Прогноз возрастёт до 61%, текущая оценка останется 56%.
3. Раскройте «Получить список оплаченных заказов». До выполнения плана полностью подтверждена одна из трёх связанных мер, после выполнения будут закрыты две. Для третьей нужно согласовать порядок восстановления.
4. Снимите пробное восстановление и сравните другой вариант — назначить дежурного и проверить доставку уведомления. Он обойдётся в один человеко-день и изменит покрытие других мер. Скачайте отчёт с выбранным планом и оставшимися пробелами.
5. Переключитесь на дизайн-студию или бухгалтерское бюро, чтобы увидеть другой процесс и набор исходных ответов. В «Моей оценке» заполните собственную анкету. Смена профиля собственной компании меняет карту процесса и сохраняет введённые ответы.

## Интерпретация

По три вопроса на резервные копии, учётные записи, устройства, обновления, мониторинг и реагирование. Баллы за меру: 2 за «Да», 1 за «Частично», 0 за «Нет» или «Не знаю». Для неизвестного состояния предлагается сначала уточнить сведения. Пропущенные вопросы блокируют итоговый прогноз. Общий процент рассчитывается от 36, раздел — от 6. На карте процесса учитываются только полностью выполненные меры.

В плане сначала идут меры с нулём подтверждённых баллов, затем частично выполненные. Внутри группы меры упорядочены по трудозатратам. Оценка усилий, равные веса и связи с бизнес-процессами — допущения учебной модели. Достижение прогноза предполагает выполнение выбранных мер и проверку по указанным критериям. Процент не является вероятностью атаки или восстановления.

## Данные и границы

Ответы собственной оценки сохраняются в localStorage браузера. Демоданные существуют в памяти и сбрасываются при смене демо-компании. Режим file:// зависит от правил браузера для локальных файлов. Перемещение папки или смена адреса может создать новое хранилище. Отчёт Markdown можно открыть обычным текстовым редактором. На общем компьютере ответы доступны другим пользователям того же профиля браузера. Входные данные ограничены фиксированными вариантами. Приложение не принимает файлы и пароли, не выполняет сетевых проверок и не отправляет ответы.

По реестру от 19 ноября 2026 года ближайшие темы KIB-24 и KIB-37 посвящены резервным копиям и рабочим аккаунтам. Здесь каждый из этих объектов занимает три вопроса из восемнадцати. Результат KIB-09 — оценка шести направлений и сравнение альтернативных планов подготовки для бизнес-процесса. KIB-01 ранжирует пути проникновения, KIB-18 посвящена действиям после инцидента. Официальный статус уникальности определяет преподаватель.

## Размещение на GitHub

Создайте репозиторий и загрузите содержимое распакованной папки так, чтобы index.html и README.md лежали прямо в корне. Для ссылки на демо откройте Settings → Pages, выберите Deploy from a branch, затем main и /(root). После публикации скопируйте адрес со страницы Pages. Для бесплатного тарифа используйте публичный репозиторий. Исходный реестр с персональными данными не входит в поставку.

## Структура и проверка

- index.html — входная страница.
- style.css — оформление и адаптивная раскладка.
- model.js — вопросы, профили, оценки и правила плана.
- app.js — анкета, диаграмма, карта процесса, выбор мер и экспорт.
- tests/model.test.js — проверка расчётов и восстановления состояния. Запуск из корня проекта на Node.js 18 или новее: `node --test`.
